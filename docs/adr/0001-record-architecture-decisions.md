# ADR-0001: 아키텍처 결정을 ADR로 기록한다

- 상태: 채택
- 날짜: 2026-08-19

## 맥락
`docs/payment-platform-design.md` 는 설계의 단일 진실(SSOT)이다. 구현 중에는 환경 제약(하드웨어 아키텍처,
이미지 가용성 등)이나 새로 알게 된 사실 때문에 설계와 다른 선택이 필요해진다. 이때 코드만 바꾸고 문서를
그대로 두면 문서-코드 불일치가 생기는데, 포트폴리오에서 이는 최악의 신호다.

## 결정
설계 문서와 다른 선택을 할 때는 **코드보다 먼저** `docs/adr/NNNN-<슬러그>.md` 를 작성한다.
형식은 맥락 / 결정 / 기각한 대안 / 결과 4단락. 번호는 순차 증가하며 기존 ADR은 수정하지 않고
"대체됨(superseded by ADR-NNNN)" 으로 표시한다.

## 기각한 대안
- 설계 문서를 직접 수정: 결정의 이력과 근거가 사라진다.
- 커밋 메시지에만 기록: 검색·리뷰가 어렵고 면접에서 보여주기 어렵다.

## 결과
설계 문서는 "무엇을 만드는가", ADR은 "왜 그렇게 만들었는가"를 담는다. README에서 ADR 목록을 링크한다.
